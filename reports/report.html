Question 3

A requirement to the project is that you include a third-party package not covered in the course. What framework did you choose to work with and did it help you complete the project?

Recommended answer length: 100-200 words.

Example: We used the third-party framework ... in our project. We used functionality ... and functionality ... from the package to do ... and ... in our project.

Answer:

For this project we used the third-party framework torchvision, and specificily the transform sub-library. We used the package functionality of being able to create a transform pipeline to modify images. We used this transform pipeline to easily resize and normalize our pictures in our data pipeline. Our images were originally 250 x 250 pixels, which is quite large given the task is to classify rice images. Hence, to save computation it was beneficial for us to make them smaller (50 x 50 pixels) and normalize all the individual pixel values. This package made it much easier for us to make these steps, as the package both comes with a pipeline setup to set these steps after each other and with build-in functions to do this. Moreover, the transform pipeline acts on the whole data set and there was therefore no need for us to loop over all the individual pictures, that was all handled by the package.

Did you implement anything extra in your project that is not covered by other questions? Maybe you implemented a frontend for your API, use extra version control features, a drift detection service, a kubernetes cluster etc. If yes, explain what you did and why.

Recommended answer length: 0-200 words.

Example: We implemented a frontend for our API. We did this because we wanted to show the user ... . The frontend was implemented using ...

Answer:

We implemented a data drifting service to monitor various metrics between the trained data and the data inputted by users. We saved the images received from API requests to a Google Cloud bucket and then loaded them into a monitoring API. This API generates reports using the Evidently library’s DataDriftPreset, DataQualityPreset, and TargetDriftPreset functions.

Since we are working with image data, we evaluated metrics such as average brightness, sharpness, and contrast. This approach allows us to detect shifts in the distribution of data characteristics over time. If significant drifts are identified, we can retrain the model to maintain or improve its performance.

The starting point of the diagram is our local setup, where we integrated ... and ... and ... into our code. Whenever we commit code and push to GitHub, it auto triggers ... and ... . From there the diagram shows ...

You can see the project arcitecture in the above figure. We have used several of the tools presetned in the course.

First, we created a GitHub repository for our project and a Google Cloud bucket for storing the data. We used dvc push to upload the data after running data.py to process the data. Since generating the data for training the model is not a step that needs to be executed multiple times initially, we did not include continuous integration for now. However, if the data changes, data.py should automatically recreate the processed data.

Regarding GitHub, we set up different actions that run tests on each push a member makes. This ensures that everything is good with the new changes. Similarly, we implemented a pre-commit hook that ensures the code aligns with proper formatting and coding standards.

For model training, we used Vertex AI by running the associated .yaml file, which trains the model and then saves it to the Weights and Biases account, enabling version control. Thus, then the prediction API can download the latest model from there without any code changes, even if we retrain the model.

We implemented Dockerfiles to build images for the different APIs (prediction and drifting), and their continuous integration happens through the .yaml files, which build the images, push them to the registry, and then deploy them to Cloud Run. This enables online access to the application for users to the prediction API. Similarly, the monitoring API compares the data provided by users with the data used for training. This happens automatically as the monitoring app reads the data from a cloud bucket where the user data has been saved and the training data from another (generated by the data.py also stored in a bucket).
